# 詞彙表格式（`--vocab`）

詞彙表把「畫面裡可能出現什麼」寫成封閉清單，讓兩個模型用同一套語言作答，也讓比對可以用程式做。

```json
{
  "classes": {
    "INST": "腹腔鏡器械（含夾口）",
    "THREAD": "縫線",
    "NEEDLE": "縫針",
    "PAD": "練習墊或組織"
  },
  "constraints": ["畫面中最多兩支器械", "器械是剛體，從畫面邊緣進入"],
  "relations": {
    "tips_together": {"between": ["INST", "INST"], "definition": "distance_pct < 5"}
  },
  "position_threshold_pct": 5,
  "max_count": {"INST": 2},
  "key_points": {"INST": "夾口尖端"},
  "track_class": "INST",
  "sam_margin_pct": 1
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `classes` | 是 | 類別代號 → 說明。清單外的物體一律記為 `other`，並附 `other_description` |
| `constraints` | 否 | 物理約束的文字說明（字串陣列），放進給兩個模型的 prompt。**只是提示，不會當成裁決證據**；要當證據的上限寫在 `max_count` |
| `key_points` | 否 | 類別 → 關鍵點定義（例如器械：夾口尖端）。**只有列出的類別要給點、比位置**；其他類別只比數量。練習墊、縫線這類沒有明確關鍵點的物件不要列：兩個模型各點一處必然相差超過門檻，會造成假分歧。代價是這些類別只比數量，它們的數量分歧無法裁決（見下） |
| `relations` | 否 | 關係名 → `{"between": [類別, 類別], "definition": "distance_pct <比較符號> <數值>"}`。兩個類別都必須在 `key_points` 裡。`distance_pct` 是第一類的一個關鍵點與第二類另一個關鍵點之間的**最小距離**（畫面寬度百分比），所以某類物件不只兩個時也有確定的答案；一對這樣的關鍵點都沒有時，關係為 false。其他寫法（`很近（< 5）`、`closeness < 5`、沒有門檻的「會合」）一律 `target_invalid` |
| `position_threshold_pct` | 否 | 位置差超過多少（畫面寬度百分比）算分歧，預設 5 |
| `max_count` | 否 | 類別 → 數量上限，也會寫進給兩個模型的 prompt。答案超過上限的一方在數量分歧裡被排除。單獨存在時只是排除法，不代表另一方的數量被確認；與放大輪或 SAM 看到的數量（下限）一起夾出答案時才裁決，例如 3 對 2、上限 2、放大輪兩邊都數到 2 → 判數 2 的一方 |
| `track_class` | 否 | SAM 追蹤的類別，必須在 `key_points` 裡；預設為 `key_points` 的第一個。沒有任何關鍵點類別時 SAM 為 not_applicable |
| `sam_margin_pct` | 否 | SAM 量測值離門檻多近就不算證據，預設 1（實測 SAM 與標註的距離差最大 0.91%） |

SAM 只追蹤 `track_class` 一個類別，所以 SAM 證據只用於這個類別的數量與位置分歧，以及 `between` 兩邊都是
`track_class`、定義為 `distance_pct` 的關係（追蹤物件尖端之間的最小距離，以畫面寬度百分比計）。有關鍵點的類別，
其他分歧靠放大輪。沒有關鍵點的類別只比數量：沒有放大題，SAM 也不追蹤，所以它們的數量分歧最多被 `max_count`
排除一方，**無法裁決**。

放大輪與 SAM 都只看得到一部分物件（裁切區外、沒錨定的看不到），所以它們看到的數量只是下限；量到的最小距離
只是上界，能證明「距離小於門檻」，要證明「距離不小於門檻」，得雙方對這兩類的數量一致、而且證據看到了每一個。
